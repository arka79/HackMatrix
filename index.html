Quick Start

Get CI Doctor running in 5 minutes.

1

Initialize

Creates the config file and run history store directory.

ci-doctor-arka init
2

Set Gemini API Key

Get a free key from Google AI Studio.

export GEMINI_API_KEY=your-key-here
3

Generate Demo Data

Create simulated test runs to try out the commands.

ci-doctor-arka demo seed
4

Analyze JUnit XML

Point at your CI's JUnit XML results file.

ci-doctor-arka analyze path/to/results.xml --commit abc123 --branch main
5

Get Root Cause

Ask AI to explain why tests failed.

ci-doctor-arka explain latest --provider gemini

Command Reference

All available CLI commands and their options.

ci-doctor-arka init [path]

Write a default cidoctor.toml and create the .cidoctor/runs/ directory.

ci-doctor-arka init [path]
ArgumentDefaultDescription
pathcidoctor.tomlPath to the config file to write.
ci-doctor-arka analyze <file>

Parse a JUnit XML results file, fingerprint failures, and save the run.

ci-doctor-arka analyze <file> [options]
OptionDefaultDescription
<file>RequiredPath to the JUnit XML results file.
--commitAuto-detectedCommit SHA (auto-detected with git if omitted).
--branchAuto-detectedBranch name (auto-detected with git if omitted).
--logNonePath to a log file (accepted for interface parity).
--formattableOutput format: table or json.

Example

ci-doctor-arka analyze junit.xml --commit abc123 --branch main --format json
ci-doctor-arka flaky

Show flaky-test verdicts ranked by confidence from stored run history.

ci-doctor-arka flaky [options]
OptionDefaultDescription
--since14dLook back this long (e.g. 14d, 12h, 90m).
--min-runsConfig valueMinimum runs for a conclusive verdict.
--formattableOutput format: table or json.

Example

ci-doctor-arka flaky --since 14d --format json
ci-doctor-arka explain [run-id]

Explain the root cause of a run's failures using Gemini or Ollama.

ci-doctor-arka explain [run-id] [options]
OptionDefaultDescription
run-idlatestRun id or 'latest'.
--providergeminiProvider name (e.g. gemini, mock).
--modelConfig valueModel name (provider-specific).
--agent / --no-agent--agentUse the investigation agent (default on).
--formattableOutput format: table or json.

Example

ci-doctor-arka explain latest --provider gemini --format json
ci-doctor-arka launch [run-id]

Discover models, pick one, and run the agent investigation.

ci-doctor-arka launch [run-id] [options]
OptionDefaultDescription
run-idlatestRun id or 'latest'.
--model, -mNoneModel name (e.g. gemini-3.5-flash-lite, llama3).
--configFalseSave the model choice to cidoctor.toml and exit.
ci-doctor-arka comment [run-id]

Post a CI Doctor report as a GitHub PR comment.

ci-doctor-arka comment [run-id] [options]
OptionDefaultDescription
run-idlatestRun id or 'latest'.
--dry-runFalsePrint the comment body instead of posting.

Example

ci-doctor-arka comment latest --dry-run
ci-doctor-arka demo seed

Generate deterministic simulated demo data for testing.

ci-doctor-arka demo seed

What it creates

  • 30 simulated runs (~60 tests each)
  • test_00: consistently failing
  • test_01 and test_02: flaky (alternate pass/fail)
  • Remaining tests: consistently passing

Real-World Examples

Common debugging scenarios with CI Doctor.

Debug a single failing build

Your CI build just failed. Find out why quickly.

# 1. Analyze the JUnit XML from your CI
ci-doctor-arka analyze junit.xml --commit $(git rev-parse HEAD) --branch main

# 2. See failure groups
ci-doctor-arka analyze junit.xml --format json

# 3. Get AI explanation
ci-doctor-arka explain latest --provider gemini

Find flaky tests over 2 weeks

Identify tests that intermittently pass/fail.

ci-doctor-arka flaky --since 14d --format table

Look for verdicts of flaky or failing with high confidence.

Post a PR comment automatically

Add CI Doctor results to your GitHub PR.

# Preview first
ci-doctor-arka comment latest --dry-run

# Then post for real
export GITHUB_TOKEN=your-token
export GITHUB_REPOSITORY=owner/repo
ci-doctor-arka comment latest

Use Ollama for offline AI

Run CI Doctor without sending data to external APIs.

# Pull a model
ollama pull llama3

# Launch investigation
ci-doctor-arka launch latest --model llama3

Debugging Guide

How to use CI Doctor effectively for debugging.

1

Analyze the failure

Start by parsing your JUnit XML to see what failed.

ci-doctor-arka analyze results.xml --commit abc123 --branch main --format json
  • Check the failure groups section
  • Note the fingerprint for each group
  • Review the sample messages and affected tests
2

Check if it's flaky

Determine if this is a one-off or recurring issue.

ci-doctor-arka flaky --since 14d
  • failing = consistent failure (likely a real bug)
  • flaky = intermittent (timing, race conditions)
  • stable = consistently passing
  • insufficient_data = not enough runs yet
3

Get AI diagnosis

Ask Gemini to explain the root cause.

ci-doctor-arka explain latest --provider gemini
  • Read the root cause and category
  • Apply the suggested fix
  • Check confidence score (0-1)
4

Share with team

Post results to your PR or ticket.

ci-doctor-arka comment latest --dry-run
  • Review the generated Markdown comment
  • Post it to your GitHub PR
  • Link to the CI run for context

Troubleshooting

ProblemSolution
No parser found for path/to/file.xml Make sure the file exists and ends with .xml. Provide the full path.
GEMINI_API_KEY environment variable is not set Export your key: export GEMINI_API_KEY=your-key. Or use --provider mock.
Run 'latest' not found Run ci-doctor-arka analyze or ci-doctor-arka demo seed first to create runs.
No provider found for 'name' Use gemini, ollama, or mock. Check spelling.
Unknown model For Ollama: run ollama pull <model> first. For Gemini: check your API key has access.
